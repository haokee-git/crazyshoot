# CRAZYSHOOT 0.14.0 修复交付

原审计日期：2026-11-06；本次地图/材质/梯子修订：2026-11-07，Asia/Shanghai。单 agent 顺序实施；没有使用子代理，没有部署。

本轮已修改源码，实施核心正确性、炮塔/倒车、弹道、加载与联机修复；按最新反馈重做了地形、掩体、写实像素材质、坑洞和可爬梯子。**没有把77项全部标为完成**；下表明确保留设计、功能和真机验收缺口。

## 证据与重跑

- 原UI版本0.12.0、原package版本0.1.0；修复后统一0.14.0。目录没有Git，原始源码见 `source-before.tgz`；新文件/修改清单见 `changed-files.json`，最终哈希见 `source-after-sha256.json`。
- `request.md`保存原请求，`original/`保留原截图、evidence.json、CPU profile和地图草案，未覆盖原始证据。
- `before.json`记录修复前可复现的V01/P15/N01/M03/N02/V04；`after.json`使用相同类型的行为断言。P01慢加载另由两端延迟资源验证。
- `maps.json`：四正式图与训练场、12v12、每端出生到A/B/C导航可达、GPU计数和截图。始终验证24实体，开局不重复补bot。
- `network.json`：两端慢资源屏障、客机不能独自跳整备、房主死亡/换装不停止客机、换装期间不复活、AWM复活弹药5/25、权威射击与离开清理。
- `rules.json`：占点时间/高度/中和、满分胜利/平局、赛后冻结、桥/水、烟雾、爆炸遮挡/车舱保护和context-loss提示。
- `lifecycle.json`：默认窗口、真实暂停、资源失败重试、100次换枪与100次尸体GPU循环。这是函数级压力，不是100次完整联网重生流程。
- `vehicles.json`与 `tank-controls.webm`：实际地图四组合转向、前行制动惯性、炮塔未对齐抢射的真实炮口。
- 单元测试32项通过；`npm run build`通过。单测覆盖弹道10/50/100m、20/30/60fps等价落点、薄墙、双线性地形擦顶、轴加速度/限位/跨π、跳跃与疾跑和限帧抖动。

本轮浏览器使用1280×720，另有1024×768装备页截图；质量low，AI种子1106。测试中有明确的内存状态注入、可控位置和暂停循环。原报告1440×900计数与本轮1280×720快照不能直接计算百分比降幅；同视角比较另列配对证据。

## 已知验收边界

没有J1900硬件访问，硬件WebGL2、旧核显、DDR3/4GB、GPU计时/显式字节数和浏览器进程工作集都未测。CPU降速与M5结果不能代替真机。没有完成受控50/100ms RTT、丢包、抖动、三局耐久和所有斜坡/移动靶矩阵。

最新用户约束为：接近现实的军事场景，仅地图采用全方块构造和32/64像素贴图，保留原天空盒。采用同源体素、简化动态OBB、固定60Hz、共享流场、刚性骨骼合批和小型对象池。没有引入大型物理/导航框架；SSAO、SSR、级联阴影、完整ragdoll和全图高成本室内不采纳为默认低配路径。早先连续地表版本及其数据归档在 `previous-continuous/`，不能用作本版验收。四图仍需真人对战平衡。
